## Task 1: 잘린 단위·로그형 범위 추정 — `src/logic_mcp/logic/values.py` `infer_mapping`
- 상수 `LCD_CELL = 6` (LCD 한 칸 폭) 추가.
- 헬퍼 `_unit_compatible(lo: Value, hi: Value) -> bool`: `lo.unit == hi.unit`이면 True. 아니면 한쪽 단위가 None이거나 다른 쪽 단위의 접두(`'m'`은 `'ms'`의 접두)이고, **그쪽(짧은 단위 쪽) 텍스트 길이가 `LCD_CELL` 이상**이면 True(잘림으로 간주). 그 외 False.
- `infer_mapping`: 단위 검사를 `_unit_compatible`로 교체. 단위 호환 뒤, `lo.number > 0 and hi.number > 0 and max(lo,hi)/min(lo,hi) >= 100`이면 `Mapping("log", lo, hi)`; 기존 Hz 규칙 유지; 나머지 linear.
- 테스트(`tests/test_values.py`):
  - `('5.0 ms','5000.0')` → `Mapping("log", 5.0, 5000.0)` (실측: Compressor Release 페이더 1·16383)
  - `('5.0 ms','160.0 m')` → linear(5, 160) (비율 32 < 100, 단위 `m`은 `ms` 접두·텍스트 7자)
  - `('91.4 s','183 ms')` → None (기존 Space Designer Length 테스트 유지: `s`는 `ms`의 접두가 아님)
  - `('0.0 ms','5000.0')` → linear (lo=0은 log 불가)
  - `('3 dB','5000.0')` → None (`'3 dB'`는 4자 → 잘림 아님)
- 커밋: `fix(values): accept LCD-truncated units and infer log mapping for wide positive ranges`

## Task 3: enum 선택지를 번호로 — `setter.py`, `plugin.py` `set`
- `setter.py`에 `set_enum_index(d: ModeDriver, ch: int, n: int, options: list[str] | None, max_options: int = 16) -> SetOutcome`:
  - `n < 1` 또는 (`options`가 있고 `n > len(options)`)이면 `SetOutcome(False, d.read_value(ch), 0, f"#{n}: 선택지 {len(options)}개 범위 밖")`.
  - 틱 −1을 `max_options`회(끝에서는 무변화라 첫 선택지에 닿음), 이어서 +1을 `n-1`회. 매 틱 뒤 `d.settle_overlay()`는 calibrate와 같게 호출.
  - `cur = d.read_value(ch)`. `options`가 None이면 `SetOutcome(True, cur, steps, "no_options")`. 있으면 `ok = cur.text == options[n-1]`, note는 ok면 `""`, 아니면 `f"#{n} 도착 텍스트 {cur.text!r} ≠ 표 {options[n-1]!r}"`.
- `plugin.py` `set`의 enum 분기(`else: want = ...; out = set_enum(d, col, want)`)를 다음으로:
  - `options = (item.get("map") or {}).get("options")` (map type이 enum일 때만).
  - `want`가 `#<숫자>` 형식(`re.fullmatch(r"#(\d+)", want)`)이면 `set_enum_index(d, col, n, options)`.
  - 아니고 `options`가 있으면 `hits = [i for i, o in enumerate(options, 1) if o == want]`: 1개 → `set_enum_index(d, col, hits[0], options)`; 2개 이상 → `b._result(action, False, "skipped", ..., note=f"{want!r}가 {len(hits)}개({', '.join(f'#{i}' for i in hits)}): 번호로 지정")`을 바로 반환; 0개 → 기존 `set_enum(d, col, want)` (전체 이름 'On'/'Off' 등 축약 아닌 입력 경로 유지).
  - `out.note == "no_options"`이면 결과는 ok=True, `verified="unverified"`, note `"선택지 표 없음(calibrate 전): 도착 텍스트만 보고"`.
  - 그 외 기존대로 `after`·`verified` 계산.
- 테스트:
  - `tests/test_setter.py`: 가짜 enum 파라미터 options `['PltDig','Studio','Studio','Classc','Vintag','Vintag','VinOpt']`(fakes에 겹침 지원이 없으면 추가)에서 `set_enum_index(n=6)` → ok, text `'Vintag'`, 보낸 틱이 −1 16회 뒤 +1 5회. `n=8` → ok False, note에 `범위 밖`. options None → note `"no_options"`.
  - `tests/test_assign_plugin.py`: 표에 위 options가 있는 플러그인에서 `set(..., "#6")` → verified; `set(..., "Studio")` → `skipped`, note에 `#2`와 `#3`; `set(..., "Classc")` → verified(번호 경로); 표 없는 플러그인에 `"#2"` → ok, verified `"unverified"`.
- 커밋: `feat(plugin): select enum options by index (#n) and refuse ambiguous abbreviated names`

## Task 4: calibrate 선택지 수집을 고정 횟수로 — `plugin.py` calibrate(enum 분기, 약 749~770행)
- 되감기: "텍스트가 안 바뀌면 멈춤" 루프를 틱 −1 `MAX_OPTIONS`회로 교체(이름 캡처 `if d.tick(...) and name is None:` 로직은 유지).
- 전진: 첫 텍스트를 읽고 +1 틱을 `MAX_OPTIONS - 1`회 보내며 매번 텍스트를 모은다(같아도 멈추지 않음). 끝에서 **뒤쪽에 연속으로 같은 텍스트가 반복되는 구간은 하나만 남기고 잘라낸다**. 중간의 겹침(`'Studio','Studio'`)은 그대로 둔다.
- 기존 "상한까지 모인 숫자 선택지 → 프로빙" 분기는 유지(잘라낸 뒤 길이로 판단하면 동작이 달라지므로, 잘라내기 **전** 길이 `MAX_OPTIONS` 도달 + 전부 숫자일 때 프로빙).
- 테스트(`tests/test_calibrate.py`): 가짜 플러그인에 Circuit Type처럼 겹치는 7개 선택지 → 수집 결과 options가 7개 순서대로. 기존 calibrate 테스트 전부 통과.
- 한계(문서용, 코드 주석에 한 줄): 진짜로 끝에 같은 텍스트가 연속되는 선택지는 하나로 합쳐진다.
- 커밋: `fix(calibrate): collect enum options with fixed tick counts so duplicate texts are kept`
