## Task 4: scripts/smoke_stdio.py
- 40줄 안팎. 사용: `uv run python scripts/smoke_stdio.py [명령…]`(기본 `uv run logic-mcp`). 자식 프로세스를 `subprocess.Popen(cmd, stdin=PIPE, stdout=PIPE, stderr=DEVNULL, text=True)`로 띄우고 한 줄 JSON `{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"smoke","version":"0"}}}` + `\n`을 쓴 뒤 stdout 첫 줄을 **스레드로 최대 30초** 기다린다. 응답의 `result.serverInfo.name`·`version`을 `ok name=logic-mcp version=…` 한 줄로 찍고 exit 0; 없으면 `fail: <이유>` 한 줄, exit 1. 끝나면 stdin을 닫고 `terminate()`·`wait(5)`.
- 검증: `uv run python scripts/smoke_stdio.py` → ok. `uv run python scripts/smoke_stdio.py uvx --python 3.12 --from . logic-mcp` → ok(로컬 경로 설치. 네트워크에서 git 설치하는 검증은 계획 작성자가 push 뒤에 한다). 두 결과를 보고서에 그대로 적는다.

## Task 5: docs/troubleshooting.md
- 출처: `docs/mcu-protocol.md` 84행(Z6)·106행·120행(Z10)·123~124행(Z11·Z11-b)·126행(Z12)·129행(Z14)·131행(Z16)·132행(Z17). **그 항목에 적힌 사실만** 쓴다.
- 구조: 머리말("위에서 아래 순서로 확인") 뒤 절 6개.
  1. `logic_session wait_ready`가 `no_logic`/timeout: ① Logic 실행 중인가 ② 프로젝트가 열려 있는가('시작' 대화상자만 떠 있으면 서피스가 멈춘다, Z11) ③ 모달 알림이 떠 있는가(예: 이어폰을 뽑으면 "마지막에 선택한 오디오 인터페이스를 사용할 수 없습니다" — 확인을 누르면 즉시 재연결, Z10) ④ Logic > 설정 > 컨트롤 서피스 > 설정에 Mackie Control이 없거나 2개(Z6·Z14): Mackie Control 항목만 삭제 → 서버를 다시 시작하면 Logic이 1개를 재설치 → `logic_session configure`. 다른 장치 항목은 건드리지 말고 "기본값 재형성"은 누르지 말 것.
  2. `configure`가 unverified: NAME 표시 상태가 남는 경우(Z12)와 PAN 2행 `-`(Z17)는 configure가 자동 복구한다. 그래도 안 되면 1-④.
  3. EQ·PLUGIN·SEND 버튼이 반응 없음(Z6): 1-④.
  4. 편집 뷰에 들어갈 때 플러그인 창이 열림: 컨트롤 서피스 설정 창 CS 그룹의 `플러그인 윈도우 열기/닫기` 체크 해제(Z17 캡처에서 확인한 항목. 해제 뒤 동작은 미측정이라고 적는다).
  5. `page_to … 커서 반응 없음`(Z16): 서버가 3초 더 기다린 뒤 한 번 재누름. 그래도 실패하면 같은 명령을 다시.
  6. 연속 set 직후 값이 빈 칸/이전 값(Z15): 페이더 값 오버레이가 약 2초 남는다. 2초 뒤 다시 읽는다(set 경로 자동 대기는 아직 없음).
- README의 "주의" 둘째 항목(Z6 절차)은 이 문서로 링크를 걸고 한 줄로 줄인다.
