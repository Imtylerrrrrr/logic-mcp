## 정할 것 (사용자)

**스테레오 두 벌 배치에서 이름으로 `set`하면 어디에 쓸까.**

## 정한 것

- **저장 형식**: `params[이름]`은 지금처럼 `{"pages", "items"}`이고 이것이 첫 배치다. 다른 배치는 그 안의 `"layouts": [{"pages", "items", ...}]`에 둔다. 배치에 붙는 선택 키: `"copies": 2`(두 벌), `"format": "m/m"|"s/s"`(수집한 형식, 사람이 읽는 용도. 코드는 읽지 않는다). 옛 사용자 캐시(키 없음)는 그대로 읽힌다.
- **배치 고르기**(편집 뷰를 열고 NAME 모드가 된 직후, 아래 순서 그대로):
  1. 화면 2행 8칸을 읽는다(`_name_cells`: 7자씩 strip, `EMPTY_SHORTS`는 `""`).
  2. 페이지 수: 헤더에 `Page n/N`이 보이면 N. 아니면 항목이 있는 배치 중 1페이지짜리의 1페이지 이름이 화면 8칸과 **전부**(빈칸 포함) 같으면 1(커서를 누르지 않는다). 아니면 `probe_pages(expect)`, expect = 항목이 있는 배치가 있고 전부 2페이지 이상이면 `2`, 그 밖은 `None`.
  3. 후보 = 항목이 있는 배치 중 `pages`가 같은 것.
     - 1페이지: 후보 중 1페이지 이름이 8칸과 전부 같은 첫 배치.
     - 2페이지 이상, 후보 1개: 그 배치(이름을 비교하지 않는다. Logic은 직전에 보던 페이지에서 편집 뷰를 열기 때문에(11/25 11:10 트랙 12·15가 `Page 3/3`·`Page 2/3`에서 열림) 매번 1페이지로 가면 Space Designer 같은 긴 플러그인에서 누름이 수십 번 늘어난다. 잘못 골랐다면 페이지 가드가 거부한다).
     - 2페이지 이상, 후보 여러 개: `page_to(1)` 뒤 8칸을 다시 읽어 전부 같은 첫 배치.
  4. 못 골랐으면 항목이 빈 배치를 재사용(`pages` 갱신), 그것도 없으면 `add_layout`.
- **두 벌 배치(`copies: 2`)**: `items`(index 순)의 앞 절반이 첫 묶음, 뒤 절반이 둘째 묶음이고 k번째와 k + 절반 번째가 짝이다.
  - 이름·축약명으로 찾기: 첫 묶음에서만 찾는다. index로 찾기: 그 항목 하나(짝을 건드리지 않는다).
  - `set`(이름): 첫 묶음을 맞추고 → `settle_overlay()` → `flip(False)` → `toggle_name_value()` → 짝을 **같은 목표 값**으로 맞춘다. 첫 묶음이 실패하면 짝은 보내지 않는다.
  - 결과: `before`·`after`는 첫 묶음 것 그대로, `after["twin"] = {"index", "value", "text"}` 추가. 짝이 실패하면 `ok=false`, `verified` = 짝의 verified, note `둘째 묶음(index N) 실패: <짝 note>`. 둘 다 ok인데 `text`가 다르면 `ok=false`, `unverified`, note `둘째 묶음(index N) 값이 다름: <짝 text>`. 둘 다 ok면 note는 첫 묶음 note, `verified`는 둘 중 하나라도 `verified`면 `verified`, 아니면 첫 묶음 것.
  - `set_many`: 이름으로 준 항목은 위와 같이 짝까지 쓰고 항목 결과에 `"twin"`을 넣는다. 중복 검사는 "쓰게 될 항목" 기준(이름 항목은 첫 묶음 + 짝, index 항목은 하나)으로 하고 겹치면 지금과 같은 `changes k번째: <short>가 두 번 나옴`.
  - `params`: 항목은 지금처럼 전부 돌려주고, `after["copies"] = 2`와 둘째 묶음 항목의 `"copy": 2`를 추가한다. `get`은 바꾸지 않는다(이름이면 첫 묶음 값).
- `copies`는 번들 데이터에만 손으로(수집 스크립트로) 넣는다. 화면에서 새로 배운 배치에 자동으로 붙이지 않는다(이름이 우연히 반복되는 플러그인을 두 벌로 오인하면 다른 파라미터에 값을 쓰게 된다).
- 번들 `generated`가 바뀌므로 사용자 캐시에 있던 번들 플러그인의 표(형식이 섞여 덮인 것 포함)는 기존 규칙(M2)대로 버려진다.
