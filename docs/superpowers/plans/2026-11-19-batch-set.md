## 정한 것

- **입력**: `changes` 배열. 플러그인 `{param, value, tolerance?}`, EQ `{band, param, value}`. 1~32개(32 = EQ 전체 8밴드 × 4값). `param`·`value`(·`tolerance`)와 같이 주면 skipped. 한 개 형식은 그대로 둔다.
- **순서**: 받은 순서대로. 정렬하지 않는다(멈췄을 때 `remaining`이 예측 가능해야 한다).
- **보내기 전 검사**: 모든 항목을 먼저 확인하고 하나라도 틀리면 아무 값도 바꾸지 않는다(skipped, note 앞에 `changes k번째: `). 플러그인은 편집 뷰를 연 뒤 `_locate`로 전부 찾는다(읽기만 한다). EQ는 뷰에 들어가기 전에 밴드·param 조합·값 형식을 본다. 같은 파라미터가 두 번 나오면 skipped.
- **실행 중 실패**: 항목 결과가 `ok=false`면 거기서 멈춘다. 뒤 항목은 보내지 않고 `remaining`으로 돌려준다. 이미 바꾼 값은 되돌리지 않는다. `already`(ok=true)는 계속한다. 항목 실행 중 `ModeError`·`ValueError`도 그 항목의 실패로 기록하고 멈춘다(앞 항목 결과를 잃지 않는다).
- **항목의 시작 상태**: 모든 항목은 낱장 set이 보는 것과 같은 상태에서 시작한다. 둘째 항목부터는 먼저 `settle_overlay()` → `flip(False)` → (플러그인만) `toggle_name_value()`로 NAME 모드. 이 전환들은 모두 낱장 set·params가 이미 실기에서 쓰는 것이다.
- **결과**: `ToolResult` 형식 그대로, `before=None`.
  - 플러그인 `after = {"plugin", "slot", "results", "done", "remaining"}`, 항목 = `{"param"(받은 그대로), "index", "short", "name", "ok", "verified", "before": {"value","text"}|None, "after": {"value","text"}|None, "note"}`.
  - EQ `after = {"results", "done", "remaining"}`, 항목 = `{"band", "param", "ok", "verified", "before": {"value","text"}|None, "after": {"value","text"}|None, "note"}`.
  - `done` = ok인 항목 수, `remaining` = 실행하지 않은 changes(받은 그대로, 실패한 항목은 포함하지 않는다).
  - 최상위 `ok` = 전부 ok. `verified` = 실패로 멈췄으면 그 항목의 verified, 아니면 unverified가 하나라도 있으면 `unverified`, verified가 하나라도 있으면 `verified`, 전부 already면 `skipped`.
  - `note` = 성공 `"N개 완료"`, 실패 `"N개 중 M개 완료, k번째 <이름> 실패: <항목 note>. 남은 R개는 보내지 않음"`. EQ에서 삽입이 일어났으면 앞에 `"Channel EQ 삽입됨. "`을 붙이고, 그때 verified는 낱장과 같이 `verified`(ok) / `unverified`(실패)다.
